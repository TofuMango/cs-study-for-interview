## 📌 학습 내용 요약

### <span style='background-color: #ede6b1'>[해시테이블]</span>
- **`해시테이블(hash table)`** : `키(key)`와 `값(value)`의 대응으로 이루어진 표와 같은 형태의 자료구조
  - 해시 테이블 구조
    - `키(key)` : 해시 테이블에 대한 입력
    - `값(value)` : 키를 통해 얻고자 하는 데이터
      - 값의 저장위치 : `버킷(bucket)`
      - 저장된 데이터의 수 / 버킷의 수 : `로드팩터(load factor)`
      -> 해시 테이블이 얼마나 가득 차있는지에 대한 지표
      -> 로드 팩터가 클수록 해시 테이블의 성능이 떨어진다
    - `해시 함수` : 키를 인자로 활용해 인덱스를 반환(해시함수에 키를 통과 시켜 원하는 버킷에 접근)
    
  - 삽입/삭제/검색 연산의 시간복잡도 : **`O(1)`**
  -> 실행과 무관하게 항상 일정한 속도 보장
  
  - 단점
    - 속도가 빠르지만, 상대적으로 많은 메모리 공간 소모됨
    -> 데이터가 많을 수록 공간 복잡도가 시간복잡도만큼 우수하지 않다.

### [해시 함수]
- **`해시 함수(hash function)`** : 임의의 길이를 지닌 데이터를 고정된 길이로 변환하는 단방향 함수
-> 특정 입력 데이터를 고정된 길이의 해시값으로 변환 O
-> 해시값을 토대로 어떤 데이터가 입력되었는지 도출 X

  - 해시 함수의 연산방법
    - `해시 알고리즘` : MD5, SHA-1, SHA-256, SHA-512, HMAC 등
    -> sha-1의 경우 `해시 충돌`이 발생할 수 있어 역사속으로 사라짐
  
  - 활용
    - 무작위 값을 만들거나 단방향 암호를 만들 때
    - 데이터의 무결성을 검증할 때
    
  - 단순 구현
    > ✅ **모듈러 연산** 
    'A mod B' - A를 B로 나눈 나머지
    ex) 10 mod 3 = 1
    ❗ 단, 이렇게 구현할 경우 `해시 충돌`의 우려가 있다.

### [해시 충돌]
-**`해시 충돌`** 서로 다른 키에 대해 같은 해시 값이 대응되는 상황
ex) 다른 이름에 같은 전화번호가 대응된 상황

- 대표 case 
  - SHA-1
  
  > 파일1.pdf와 파일2.pdf는 서로 다른 pdf파일이다. 그러나 해시값을 구할 경우 sha-1 알고리즘에서만 동일한 해시값이 도출된다.(충돌발생)
  
    - 해결방안
      1) `체이닝(chaining)` : 충돌이 발생한 데이터를 연결리스트로 추가하는 방법
      -> 서로 다른 키가 같은 위치로 해시되어도 단순히 연결리스트의 노드만 추가됨.
      
      > ❗ 단, 충돌이 발생할 때마다 노드가 추가된다면 빠른속도라는 장점이 사라짐
      
      ![](https://velog.velcdn.com/images/yjlee0006/post/d9e8c024-03a7-4c85-97e2-b618a90e0025/image.png)

      2) `개방주소법(open addressing)` : 충돌이 발생한 버킷의 인덱스가 아닌 다른 인덱스에 데이터를 저장하는 방법
        - `조사(다른 버킷의 인덱스를 찾는 과정)`방법에 따른 구분
          - `선형 조사법` : 충돌이 발생했을 때, 충돌이 발생한 인덱스의 다음 인덱스부터 순차적으로 가용한 인덱스를 찾아 나서는 방법
          ![](https://velog.velcdn.com/images/yjlee0006/post/b30a3c5e-8c9b-445c-9924-f343507f2bab/image.png)

          > ❗ 충돌이 발생하는 인덱스 인근에 데이터가 몰려 저장될 수 있음(군집화)
          
          - `이차 조사법` : 충돌이 발생한 인덱스에서 제곱수만큼 떨어진 거리에 위치한 인덱스를 찾는 방법
          
          ex) bucket의 크기는 7, key값 8에 대해 해시 값 10(h(8) = 10)이라고 가정
          
            (1) h(8) mod 7 = 10 mod 7 = 3         // 1차 충돌 발생 가정
            (2) (h(8) + 1^2) mod 7 = 11 mod 7 = 4  // 2차 충돌 발생 가정
            (3) (h(8) + 2^2) mod 7 = 14 mod 7 = 0 // 3차 충돌 발생 가정
            (4) (h(8) + 3^2) mod 7 = 19 mod 7 =  5 // 저장

	> ❗ but 제곱수의 규칙성으로 인해 근본적인 해결 X

## 📈 추가 학습 필요
데이터가 많아질 경우 다른 데이터가 같은 해시 값으로 충돌이 발생하는 현상을 감수하면서도 해시 테이블을 사용하는 이유가 궁금해서 찾아보았다.

- 적은 자원으로 많은 데이터를 효율적으로 관리하기 위함
- 하드디스크나 클라우드에 존재하는 무한한 데이터들을 유한한 개수의 해시값으로 매핑
- 언제나 동일한 해시값 리턴 : index를 알면 빠른 데이터 검색이 가능해짐
-> 해시테이블의 시간복잡도 O(1) - (이진탐색트리 O(logN))
